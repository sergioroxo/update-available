## 1. THE UPDATE LOGIC (Q2 — promote to core mechanic)

Sérgio's insight: *"update yourself" is simultaneously the logic of conversion
therapy, the logic of software, and a potential title.* Adopted as the
**era-transition mechanic** — the rebranding no longer happens *between*
stages; it arrives **as a software update the user must accept.**

### 1.1 The Update sequence (replaces v0.2's "lights-down" era transitions)

Each stage boundary becomes a four-beat ritual (~45–60s):

1. **The notification.** Mid-desktop, the era's own UX: a balloon (95) → a
   shield popup (XP) → a soft banner (pastel) → a silent badge (dark). *"An
   update is available. Your system needs to change."* Options:
   **"Update now"** / **"Remind me later"** — and *Remind me later works*,
   once: the desktop continues for ~20s, then the notification returns,
   slightly larger. (The Offer's refusal ladder, seeded three stages early —
   the player has already learned the system's patience before the Offer
   weaponizes it.)
2. **The EULA.** A terms-of-service wall, scroll required, one live button:
   **"I Agree."** The text is composed period-legalese in which the era's
   *actual rhetoric shift* is buried as clauses (*"…references to 'cure'
   are hereby renamed 'support'…", "…the Service may contact you through
   trusted community partners…"*). Decline is greyed (ArenaAI #6's greyed
   link, generalized). **This is consent theater as a mechanic** — the
   document everyone signs and nobody reads is how the rebrand legalizes
   itself. Dossier-annotated at the Close.
3. **The install.** Progress bar + **changelog** — the thesis as patch notes:
   > `WHAT'S NEW IN VERSION 2.0` ·
   > `— "Change is possible" is now "Managing your attractions"` ·
   > `— Improved family connectivity` ·
   > `— Your data has been migrated`
   Behind the bar, **glitch web aesthetics** (Sérgio Q2): the old era's
   chrome tears, tiles, ghost-frames into the new — the one place the piece
   is allowed visual violence, because it is the *system* convulsing, not the
   person. (Room re-dresses during the glitch in both cameras.)
4. **The restart.** Black. The new era boots. *"Welcome back, [name].
   Everything is where you left it."* (It isn't. Icons moved, one thing is
   missing, the Assistant has changed — see 1.2.)

**Why this is better than the lights-down:** it converts dead transition time
into the argument itself; it gives the Paths system its skip-grammar (the
Assistant bridge in the Short Path is now literally *"installing 2 updates…"*);
and "restart" carries the born-again echo — *Update & Restart* is conversion
therapy's exact promise, in UX language.

### 1.2 The Assistant is updated, not evolved (grief seeded early)

The Assistant's form-changes ride the updates: after the Stage-3 install —
*"HELPY.EXE is no longer supported. Meet Sol."* Helpy is simply **gone**; Sol
does not remember being Helpy (*"Who? I'm Sol."*) — but the *eye motif
persists* (Q1: same/similar motif across all forms — the lateral narrative
that it was always one process). The user's relationship is repeatedly
deleted and rebranded — which is what the practices do to their own history.
The Close's "Can I help?" goodbye (v0.3) now lands on a character the system
itself discontinued three times.

### 1.3 Title direction (Sérgio: "Update xxx — we can think of ideas")

This answers the open `[NEEDS CLARIFICATION]` in PROJECT_MEMORY (public-facing
title distinct from internal "PC Simulator"). Shortlist, argued:

| Candidate | For | Against |
|---|---|---|
| **UPDATE AVAILABLE** | The notification everyone knows; mundane-ominous; reads at festival scale; no spoiler | Slightly generic in app-store contexts |
| **Update & Restart** | The born-again double meaning (restart = rebirth); names both the mechanic and the promise | Softer as a poster word |
| **Mandatory Update** | Coercion stated in UX language | Tips the hand; less invitation, more verdict |
| **Version History** | The rebranding timeline as changelog; elegant for the academic frame | Cool/cerebral; weak in VR-festival listings |
| **UPDATE: YOU** | Thesis, direct | On-the-nose; loses the deniability the piece trades on |

**Lean: *UPDATE AVAILABLE* public title, with "Update & Restart" held as the
strongest alternate** (and as a chapter/Offer-screen phrase either way).
Internal name stays PC Simulator. → Decide later; record in BUILD_LOG when
chosen.

## 2. THE RESPITE REGISTER (point 1 — "peace in the middle")

Sérgio: the topic is heavy; the experience needs **regulated, gamified, guided
relief** — TransJesus dance stream, SOGICEfy/iPod playing songs, his existing
mini-games. Formalized as a third register value (extends v0.3 Part VI):

`register: "operable" | "felt" | "respite"`

**Respite = genuine queer joy and play. Hard rules:**
1. **Respite is never a trap.** This resolves the old `[NEEDS CLARIFICATION]`
   (affirming-space-as-trap worry, ARTIFACT_DESIGN/ETHICS): the system may
   prowl *around* a respite space (an ad tries to load against the stream; a
   classification tag tries to attach) — **but it never gets in, and the
   respite is never revealed as fake.** At least one space stays uncorrupted
   per run. Pedagogically essential: the piece must never teach "queer
   community = bait" (the classroom guide's worry, now solved structurally).
2. **Respite is where the body recovers** — Batson release-valve logic
   (ETHICS §distress): place a respite beat after each stage's Witness flip,
   before the next update notification. The emotional wave: warmth →
   intrusion → witness → **breath** → update.
3. **The dossier hands the respite back.** At C.2, alongside the name-card,
   the things the system never got: *the stream kept playing; the playlist
   was yours.*

**The respite inventory:**
- **The TransJesus dance stream** (from PARKING_LOT, now placed): a
  livestream window — an affirming, glittering, *alive* queer space (Stage 3–4
  era; pixel dance floor, chat scrolling joy, no fictional likenesses;
  queer-authored voice per *lugar de fala*). The one window the targeting
  visibly fails to enter: an ad slot beside it errors out (`content
  unclassifiable`). The system cannot read joy. ⚑ keep tone affirming;
  consult per ETHICS when text is drafted.
- **SOGICEfy player, dual life:** in `respite` use it is simply *your music* —
  an era-skinned player (K7 → NapsterFY → pod-player → streaming dark mode)
  where playing songs is pleasurable and free; its `operable`-register shadow
  (the "conversion"/sanitization mechanic, harvested from the trial) appears
  only on the **witness side** — you watch the system's copy of your library
  being "corrected." Your side keeps the real songs. Same object, two
  registers, montage logic.
- **Sérgio's existing mini-games** slot as seam-arcade objects (an in-OS
  "Games" folder, era-skinned). Inventory them in
  [PROCESS_REGISTER.md](PROCESS_REGISTER.md) (what exists, where, what state)
  and assign per-era; register `respite` unless a game is itself satirical
  (then `operable`, witness-side or perpetrator-marked).

## 3. PERSONA CARDS (Q4 — "a witness of different types of people")

Sérgio: make it a "universal" experience — personas, or even one; the user is
*witness to different types of people afflicted.* Formalization (consistent
with v0.1's one-life-per-era):

- Each stage opens with a **persona card** in the era's own UI (a user-account
  switch screen: avatar pixel-silhouette, age, city-type, one line of
  situation): *"This session belongs to ____. You'll be using their machine."*
  The user's typed name remains the constant data point; the **person changes
  per era** — the card makes the v0.1 design explicit and readable.
- Cards state their construction: **composites, labeled** (*"a composite,
  drawn from documented accounts — no real person"*) — methodological honesty
  on the surface, not only in the dossier.
- The persona set covers **different types of affliction** across stages
  (teen / young adult / adult in community / trans adult — per v0.1 stage
  castings), so "universal" = breadth-by-witnessing, not one everyman. If a
  single-persona mode is ever wanted (Sérgio's "or even just one"), it is a
  Paths variant, not a rewrite — the card system supports both.
- VR note: the account-switch card doubles as the comfort pause between
  stages (a still screen, no motion).

## 4. THE INTAKE PANEL (Q3 — path choice as boot logic)

Confirmed design: path selection happens **inside the boot, diegetically**,
before the name dialog (0.2):

> BIOS-style line during Stage-0 boot: `SESSION CONFIGURATION` ·
> `How long will this machine be yours?` · `[ A SHORT WHILE — ~15 MIN ]` /
> `[ THE FULL SESSION — ~40 MIN ]` — rendered as a period boot-menu
> (highlighted row, arrow keys / ray).

- Phrased in the machine's voice (possession language — *"yours"* — already
  doing thematic work), never as a difficulty/menu screen.
- Changeable later via the pause overlay (**Options → Session length**), as
  Sérgio specified; switching mid-run engages the Assistant bridge forward,
  or simply extends (no penalty, no comment).
- The choice is written to the ledger like everything else — and yes, the
  witness side may log it (`projected availability: 15 min`) — the system
  knew how long it had you.
