# Handheld games with tracked hands

Session S306, implemented on `codex/hand-play` (2026-11-03), from `origin/reinterp`. Held XR devices accept direct index-fingertip contact: hardware buttons have an 18 mm world-space radius, with the nearest button winning overlaps. Each hand fires once until withdrawn. CLEAR and MATCH MADE receive glass coordinates; FIT IN's glass maps its lower left/right halves to left/right and its upper third to A. Glass contact allows 12 mm of depth tolerance. Tracking loss, release, era changes and XR exit clear contact state.

`xrInput.ts` supplies the tracked index joint directly to the device through the comfort transform in `app.ts`. Unlike `points()` (used by `xrLayer.ts` for table calibration), this hand-only callback preserves source identity and excludes controller grips. Direct contact takes precedence over the former room poke and pinch path while a game is held, preventing an early ray poke followed by a second contact press; frame/menu pokes remain available. Browser ray input and controller handling retain their existing paths. No new render resources, colours, runtime network/storage, or texture-upload logic were introduced.

Checked: `npx tsc --noEmit -p .`, `npm test`, `git diff --check`, and `node tools/hand-play-probe.mjs` pass. `npm run dev -- --host 127.0.0.1 --port 5199 --strictPort` starts successfully. The probe starts Vite and headless Chrome, uses the authored device specifications and real PlayCanvas transforms with mock XR joints, and checks all eight FIT IN buttons (including 17 mm offsets), all three glass mappings, 90-frame contact holds, sliding without repeats, withdrawal/re-touch, independent hands, tracking recovery, hover rejection, menu suspension, inactive XR/resting devices, early-poke suppression, and controller A/stick edges through the real XR input loop. Run it with Node; Chrome defaults to the macOS application path, overridable with `CHROME_PATH`.

Real headset still required: Quest 3 hand-tracking accuracy and occlusion, button separation and touch comfort at the S282 scale/distance, flip-phone hinge/glass alignment, playing with the other hand while holding a device, and pickup/release/menu behavior. No real-headset performance or 72 Hz claim is made; the patch adds no draw calls. README and pre-existing workspace changes were left untouched and excluded from the commit. Nothing pushed.
