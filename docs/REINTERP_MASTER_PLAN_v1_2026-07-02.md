# 2. THE "COPY THE PROJECT" REQUIREMENT (first principles)

**Requirement zero: all reinterpretation work happens on a duplicate/branch of the repo, never in place.**
The shipped E1–3 build and the E4 spec are the funded, exhibitable asset; the reinterpretation is an
exploration that may be partly or wholly rejected. A coding agent handles git mechanics; what matters is
the *contract*:

- **The duplicate must still build and pass `npm test` (the no-network/no-storage invariants) at all
  times** — the fork inherits CI discipline, it doesn't escape it.
- **Reinterpretation content mounts behind a query flag (`?reinterp=1`), same idiom as `?flat=1`.**
  Without the flag, the fork renders the shipped piece byte-identically — this gives a permanent
  regression baseline and makes every diff reviewable as "additive module or flag-guarded hook."
- **New display text goes in new data namespaces** (`data/provotypes/`, `data/panels/`,
  `data/room/cluster4.json`) — never edits to shipped `s1_*/s2/s3/s4` files except flag-guarded hooks.
